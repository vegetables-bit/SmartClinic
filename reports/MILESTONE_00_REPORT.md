Establish a clean Django project, isolated Python environment, SQLite
development database, Git exclusions, and initial project documentation without
implementing patient, appointment, consultation, medical-history, dashboard, or
other business modules.

**Overall result: PASS.** All ten stated acceptance criteria were verified.

## 9. Problems encountered and solutions

- The workspace was not already a Git repository. Git was initialized with
  `git init`.
- Django's generated `settings.py` contained a scaffold secret key. It was
  replaced with an environment-variable requirement before Git initialization;
  no generated key is retained in tracked settings.
- Django's default URL configuration exposed the admin route but no root page.
  A minimal foundation-only landing page was added so the requested root URL
  could be verified with an HTTP 200 response.
- The Django test runner found no tests. This is expected for a foundation with
  no domain applications; the result is recorded as zero tests rather than
  claimed as test coverage.

## 13. Exact instructions for starting the project again

From a new Windows PowerShell terminal at the project root:

```powershell
.\.venv\Scripts\Activate.ps1
$env:DJANGO_SECRET_KEY = (& python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())")
python .\src\manage.py migrate
python .\src\manage.py check
python .\src\manage.py runserver
```

Open <http://127.0.0.1:8000/>. The admin site is at
<http://127.0.0.1:8000/admin/>. Set a new runtime key in each terminal before
using Django commands. If PowerShell blocks activation, use
`.\.venv\Scripts\python.exe` instead of `python`, or apply the process-scoped
activation workaround documented in the README.

To run the current test suite:

```powershell
python .\src\manage.py test
```
